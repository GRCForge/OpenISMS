# Glossary

Terms used in OpenISMS and in the regulations it covers, including the German
terms that appear in the BSI material and the German user interface.

| Term | Meaning |
|---|---|
| **AGE (Apache AGE)** | PostgreSQL extension for graph queries; powers the relationship analysis |
| **Annex A** | The 93 controls of ISO/IEC 27001:2022, in four themes: organisational, people, physical, technological |
| **AVV / DPA** | *Auftragsverarbeitungsvertrag* — data processing agreement under GDPR Art. 28 |
| **Baustein** | Module of the BSI IT-Grundschutz-Kompendium (e.g. `SYS.1.1`) |
| **BIA** | Business impact analysis — determines critical processes and their recovery objectives |
| **BSIG** | *BSI-Gesetz* — the German act implementing NIS-2 (NIS2UmsuCG) |
| **C5** | *Cloud Computing Compliance Criteria Catalogue* of the BSI; OpenISMS ships C5:2026 |
| **CAPA** | Corrective and preventive action, e.g. after an audit finding |
| **CIA** | Confidentiality, integrity, availability — the protection goals |
| **CPE** | Common Platform Enumeration — a standard identifier for software and hardware, used for CVE matching |
| **CVE** | Common Vulnerabilities and Exposures — public identifier of a vulnerability |
| **DORA** | Digital Operational Resilience Act — EU regulation for the financial sector |
| **DSFA / DPIA** | *Datenschutz-Folgenabschätzung* — data protection impact assessment under GDPR Art. 35 |
| **DSGVO / GDPR** | *Datenschutz-Grundverordnung* — General Data Protection Regulation |
| **Elementary threats** | *Elementare Gefährdungen* — the BSI's catalogue of basic threats (G 0.1 – G 0.47) |
| **Entity profile** | NIS-2 classification of an organisation: essential (*besonders wichtig*), important (*wichtig*) or indirectly affected |
| **Grundschutz++** | The BSI's successor format for IT-Grundschutz, published as OSCAL catalogues |
| **Grundschutz check** | *IT-Grundschutz-Check* — comparison of target and actual state per requirement (BSI Standard 200-2, ch. 8.4) |
| **Informationsverbund** | Information domain — the scope of an IT-Grundschutz implementation |
| **ISMS** | Information security management system |
| **KRITIS** | Critical infrastructure; under the BSIG, operators of critical facilities (*Betreiber kritischer Anlagen*) |
| **MCP** | Model Context Protocol — open protocol through which AI assistants use tools; OpenISMS ships an MCP server |
| **Modelling** | *Modellierung* — assigning IT-Grundschutz modules to target objects |
| **MTTR** | Mean time to resolve, here for incidents |
| **NIS-2** | EU Directive 2022/2555 on a high common level of cybersecurity |
| **OIDC** | OpenID Connect — the single sign-on protocol OpenISMS supports |
| **OSCAL** | Open Security Controls Assessment Language — machine-readable format for control catalogues |
| **Protection approach** | *Absicherung* in IT-Grundschutz: basic (*Basis*), standard (*Standard*) or core (*Kern*) protection |
| **RPO / RTO** | Recovery point objective (acceptable data loss) / recovery time objective (acceptable downtime) |
| **Schutzbedarf** | Protection needs — normal, high or very high per protection goal |
| **SoA** | Statement of Applicability — which Annex A controls apply, why, and their status |
| **SSRF** | Server-side request forgery — tricking a server into requesting internal addresses |
| **Target object** | *Zielobjekt* — an asset an IT-Grundschutz module is applied to |
| **TISAX** | Trusted Information Security Assessment Exchange — assessment scheme of the automotive industry, based on VDA ISA |
| **TLPT** | Threat-led penetration testing, required by DORA for certain financial entities |
| **TOM** | *Technische und organisatorische Maßnahmen* — technical and organisational measures (GDPR Art. 32) |
| **TR-02102** | BSI technical guideline on cryptographic mechanisms and key lengths |
| **VDA ISA** | Information security assessment catalogue of the German Association of the Automotive Industry |
| **VVT / RoPA** | *Verzeichnis von Verarbeitungstätigkeiten* — record of processing activities under GDPR Art. 30 |
